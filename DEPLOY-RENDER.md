# Постоянный хостинг на Render (бесплатно)

Зачем: туннель с домашнего компьютера рвётся и меняет адрес. Render даёт постоянный
адрес вида `https://max-bot-chess.onrender.com`, пока проект жив.

## Что понадобится

- аккаунт GitHub (бесплатный);
- аккаунт Render (вход через тот же GitHub, карта не нужна);
- токен бота из `bot.config.json` (поле `token`).

## Шаги

### 1. Выложить код на GitHub

1. Зарегистрируйся на github.com.
2. Создай новый репозиторий, например `max-bot-chess` (Private или Public — без разницы).
3. Загрузи туда папку `max-bot` целиком, **кроме**:
   - `bot.config.json` (это секрет);
   - `data/` (логи и состояние);
   - `node_modules/`.
4. Убедись, что в репозитории есть `package.json`, `render.yaml`, папки `src` и `public`.

### 2. Создать сервис на Render

1. Зайди на render.com → **New** → **Blueprint**.
2. Выбери свой репозиторий. Render сам прочитает `render.yaml`.
3. В переменных окружения впиши:
   - `MAX_BOT_TOKEN` = токен бота;
4. Нажми **Apply** и дождись сборки (2–4 минуты).

### 3. Проверить

Открой `https://<имя-сервиса>.onrender.com/health` — должно вернуться `{"ok":true,"games":0}`.

### 4. Привязать к боту

1. business.max.ru → **Чат-боты** → бот → **⋮** → **Настройки**.
2. В поле URL мини-приложения вставь `https://<имя-сервиса>.onrender.com`.
3. Кнопка — **Играть** → **Сохранить**.

## Ограничения бесплатного тарифа

- сервис засыпает после ~15 минут без запросов; первый запуск после сна — 30–50 секунд;
- диск не сохраняется: после перезапуска партии и споры начнутся с чистого листа
  (для споров это критично — там хранятся долги).

Если нужна永久 память, позже можно подключить бесплатную базу или перенести
`data/*.json` на внешнее хранилище. Для тестов вдвоём текущего варианта достаточно.

## Что уже готово в репозитории

- `render.yaml` — описание сервиса;
- `npm start` — запуск бота и мини-приложения одним процессом;
- `/health` — точка проверки для Render.
